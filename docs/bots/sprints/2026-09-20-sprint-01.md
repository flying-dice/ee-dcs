## Verification

`npm run test --workspace ee-mission` builds the root bundle and runs Lua 5.1 tests. Set `LUA_BIN` when Lua is not on PATH. Verified with Lua 5.1.5 on 2026-09-20:

- Strict TypeScript-to-Lua build: passes.
- Original/generated differential checks: 24 passed, covering configuration, spatial calculations, campaign state, overlays and pilots.
- Original and generated campaign smoke runs: both pass at 310 and 2100 simulated seconds (413 and 2761 timer ticks respectively).
- Smoke coverage includes reset preservation, deferred spawn tasks, numeric scenery IDs, persistence roundtrip/time rebasing, and reinjection timer cancellation.
- Eight review dimensions completed. Findings above the refactor threshold were fixed, including initialization order, external configuration validation, custom static kinds, shared type ownership and misleading names.
- A three-pass enum/numeric audit fixed the CJTF roster regression, the swallowed scenery-category lookup, neutral-to-RED regeneration, RED client-slot fallback, and invalid persisted coalition values. Gameplay literals now name their units and cite DCS, EECH, mission-format, or adapter-policy provenance; see ADR 0003.

These are offline mocked engine tests, not live DCS verification. Studio static analysis, live injection, and live economy/task-board observation remain outstanding. Lua sources are retained unchanged. No commits or pushes requested.

The web generator now uses explicit administrative territory instead of authored axes and inferred control measures. A boundary modal records BLU/RED ownership and Rear/Close role. Airbases inherit their side from containment, mains must be inside matching territory, and keysite generation applies hard role constraints: FARPs/radar in Close; factories/refineries/ports/power/command in Rear. Web type-check and production build pass.

The local OSM exporter now bakes simplified administrative level 6 relations into the paired theatre asset as typed `admin-boundary` polygons. The Caucasus rebuild produced 832 named boundaries with valid stable relation IDs; web type-check and production build pass with the enlarged static asset.

The map renders all baked administrative boundaries and opens a side-and-role modal on click. Live browser verification assigned BLU Close and RED Rear regions, confirmed the counters update, and confirmed each side's main-airbase control unlocks only after it has territory. A clean page load produced no new browser warnings or errors.

The F10 overlay audit found that the live campaign state is substantially richer than its map presentation. Base and installation summaries, individual assets, primary ground groups, one frontline midpoint and some assigned sortie lines are shown. Queued tasks, task labels/status, artillery and secondary formations, insertion/supply flights, production, ammo/fuel, regeneration, slot pressure, captures in progress, objectives, fog-of-war and importance/threat layers are not shown. The single midpoint is not the frontline used by campaign logic. Ground-column marker IDs are multiplied into the 3,000,100 range while reset only clears the 30,000 range, so reinjection can leave stale marks. Task-line failures are swallowed and the offline mocks do not validate the live DCS markup signature, leaving task-line rendering unproven until DCS Studio/live injection is available.

The mission now provides a coalition-scoped F10 operational picture with reconciled base and installation state, objectives, queued and active mission labels, primary/artillery/reserve formations, and FLOT segments derived from the campaign's Gabriel adjacency. Enemy sites and formations appear only when the coalition's fog-of-war value reaches the EECH tasking threshold, while declared objectives remain known. The Campaign radio menu provides Situation, Air Tasking, Logistics & Regen, Intelligence and Campaign Statistics reports. Stable marker pools, corrected DCS color-array markup, expanded reset cleanup and generic board-assignment registration prevent stale overlays and unlabelled helicopter/CAS/BAI sorties. Mission parity and four short/long smoke simulations pass; live DCS rendering remains pending because DCS Studio is unavailable.

The elapsed-time early/mid/late labels were removed from campaign state, persistence, announcements, status logs and pilot/F10 reports. They had no behavioural consumer and no EECH source equivalent. Campaign evolution remains driven by the ported state systems: task generators, importance/threat maps, fog of war, keysite condition, reserves, reactions, capture and victory conditions. Existing saves remain readable because the persistence validator permits the retired extra field.

Generated FARPs are fixed to DCS's stock four-position `FARP`/`FARPS` heliport, verified against a Mission Editor-authored `.miz`. Every helicopter launch path now uses DCS's heliport route fields, centres its spawn coordinates on the FARP as the editor does, and assigns parking positions 1 through 4. Real runway airbases continue to use `airdromeId`. Mission parity tests and all four smoke simulations pass; a newly generated mission still needs live visual confirmation.
