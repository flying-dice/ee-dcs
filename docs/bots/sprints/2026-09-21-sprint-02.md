## Finding that changes the plan

The smoke runs are **four independent runs**, never compared against each other
(`packages/ee-mission/test/run-tests.cjs:6-12` simply spawns each in turn and checks its exit code).
Their reported world state diverges and nothing asserts on it:

| run | ticks | groups | statics | logs |
|---|---|---|---|---|
| lua 310 s | 413 | **144** | **22** | 892 |
| ts 310 s | 414 | **146** | **23** | 721 |
| lua 2100 s | 2761 | **148** | **22** | 1509 |
| ts 2100 s | 2762 | **149** | **23** | 1184 |

So the TS tree builds a different world: +2 groups / +1 static at 310 s, +1 group / +1 static at
2100 s. The 27 "differential" checks are unit-level (`core-parity.lua`) and do not cover this.

**This is the parity gap.** "All checks pass" is true and still insufficient to justify deleting the
baseline. Until the delta is explained, the Lua tree is the only reference we have for what the
campaign is supposed to do.

## Outcome of tasks 1, 2, 2b

**A genuine port regression was found, and the Lua baseline is what proved it.**

Task 2 built the differential and it immediately failed - correctly. Task 2b then removed harness
self-contamination: the smoke test's own typescript-only fixtures (`FARP-Authored-Regression`,
`Strike-Neutral-Enum-Test`) were registering into the counted world state and consuming `next_id`,
which manufactured ~10 false one-sided diffs from ID drift. Snapshot capture was moved ahead of the
fixtures; the fixtures still run and still assert.

Task 1 decomposed the remaining delta by single-constant ablation. Cause:
`packages/ee-mission/src/task_board.ts` carried

```ts
const INITIAL_ASSIGNMENT_DELAY_SECONDS = 45;
```

against the Lua baseline's `ASSIGN_CADENCE` (180 s) for the board's first assignment pass. TS fired
the board twice in a 310 s window where Lua fired once, assigning an extra helicopter CAS section.
Its own comment admitted the value was chosen by feel - and it was masking **card 08** (CAS fires
before the spawn queue has drained, so the rotary campaign looks empty at start).

Lead applied the narrow fix - delete the constant, first fire at `ASSIGN_CADENCE` - removing an
invented number without inventing a replacement. Verified:

| | before | after |
|---|---|---|
| ticks 310 s | 413 vs 414 | **413 vs 413** |
| ticks 2100 s | 2761 vs 2762 | **2761 vs 2761** |
| spurious `Heli-CAS-2` | present | gone |
| 310 s differential | FAIL | **Differential OK** |

Neither tree is faithful to `ks_creat.c:166` (which randomises the first pass per keysite); raised as
board card 12 rather than silently substituting a derived value.

Residual at 2100 s: `Recon-1`/`Recon-2` swap trailing sequence numbers. Same entities, same counts,
same ticks - an unstable equal-priority sort (`task_board.lua:509` / `task_board.ts:528`) resolving
ties differently between Lua `table.sort` and TSTL `Array.sort`. Task 5 makes it deterministic.

## Why task 5 exists (Lead note)

Deleting the Lua tree **destroys the differential harness** - it is a migration-time instrument with
nothing left to compare against. Deleting first and noticing second would have thrown away the only
regression net we have, immediately after it caught a real regression. Task 5 converts the baseline
into golden fixtures so the net survives the deletion.
